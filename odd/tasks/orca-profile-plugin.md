# Orca profile and mode panel plugin

Objective: an Orca plugin in this repo that shows and switches the odd-flow profile and mode of each agent session, hot and without a model turn. Branch: `feat/orca-profile-plugin`. Delivery: `ask-on-risk`. Runner: `bash tests/run.sh` (shell suites) and `orca plugin test orca-plugin` (plugin).
Profile: `claude-gpt`.

## Specs

- S1 (user, verbatim): "podriamos cambiar el modo y el perfil de una sesion?"
- S2 (user, verbatim): "pero mi duda es si podriamos cambiar en caliente el perfil del flujo y el modo"
- S3 (user, verbatim): "bien, empecemos a construir el plugin, podemos agregarlo en este mismo repo?"
- S4 (user, verbatim): "vamos con el panel desde el inicio"
- S5 (assumption): the plugin lives in `orca-plugin/` in this repo, installs from a folder or a GitHub tree URL / catalog `source.path` (per `orca plugin install --help` and `orca plugin release-entry --help`).
- S6 (assumption): the MVP is the panel plus the earlier proposal: a status bar item with the focused agent's profile and mode, palette commands "odd: switch profile" and "odd: switch mode", and a one-time mode-change notice so a switch to organic takes effect mid-session.
- S7 (assumption): the plugin never re-implements bindings; it runs `skills/odd-flow/scripts/profile.py` (`use`, `session-mode`, `clear`, `list`, `show`, `mode`) with the session key variable that matches the agent (`CLAUDE_CODE_SESSION_ID`, `CODEX_THREAD_ID`, `ANTIGRAVITY_CONVERSATION_ID`) set to the `sessionId` Orca's `agents.list` reports. The `profile.py` path is a plugin setting with auto-detection of the installed odd-flow plugin.
- S9 (user, verbatim, about a worker row in the panel): "esto estaria bueno que aparezca T5 verify: panel session switching — claude — working, los controles no"
- S10 (assumption, revised 2026-11-25 after L18): a row is a worker when Orca's `agents.list` gives it a non-null `task`, or its `terminalId` is the `terminal` of any dispatch in `orca orchestration worker-list --environment local --json` (user, verbatim: "si, avanza con la lista de despachos"); the worker handlers also reject `use`, `session-mode` and `clear` for such a session.
- S11 (user, verbatim, 2026-11-25): "si, avanza con esa versión de T6" — accepting: status bar item (one coordinator in the focused workspace: `odd: <profile> · <mode>`; several: `odd: <n> sessions`; click opens the panel); command "odd-flow: Open profiles panel" with a shortcut; command "odd-flow: Toggle mode" that flips organic/full-delegation only when exactly one coordinator is in the focused workspace, otherwise opens the panel; the panel stays the way to pick a profile; opening the panel runs `orca plugin open <plugin-key> --panel <id>`; the new contributions need a new user approval. Replaces S6's "odd: switch profile" palette command (Orca commands take no input and the plugin cannot see the focused terminal).
- S8 (assumption): file-level writes (`default`, `set-mode`, `save`) stay out of the plugin's MVP; only session-scoped `use`, `session-mode` and `clear` are switched from the panel (Hard Rule 8 keeps file writes behind a confirmed diff).

## Open premises (checked in T4)

- P1: an Orca `trusted-worker` can run `python3` (child process); the plugin guide does not say.
- P2: Orca's `sessionId` (`agents.list`, `agent.status.changed`) equals the agent's own session id that `profile.py` keys on.
