# Engram worker isolation

Objective: worker sessions neither write to nor read from Engram through the agent plugins' hooks and MCP servers; the coordinator keeps its Engram use. Branch: `fix/engram-worker-isolation`. Delivery: `ask-on-risk`. Runner: `tests/run.sh`.
Profile: `claude-gpt`.

## Specs

- S1 (issue alvag/odd-flow#34, verbatim): title "Worker sessions still write to and read from Engram through the agent plugin's hooks"; body:

  > The worker roles forbid memory tools, but the Engram agent plugin's own hooks still run in every worker session, so workers write to and read from Engram anyway.
  >
  > Observed in the local Engram store for project `odd-flow` on 2026-11-26:
  > - 273 of 318 sessions have no observation at all (worker sessions registered by the plugin's SessionStart hook).
  > - Of 484 captured user prompts, 249 are worker specs ("You are working inside Orca, a multi-agent IDE. You are a dispatched worker…") and 100 are Orca orchestration mail. Only the rest are the user's own asks.
  > - As a result, the "Recent User Prompts" block that Engram injects at session start and after compaction in the coordinator shows worker specs instead of the user's requests.
  > - Each Claude worker also receives Engram's session-start memory context and a UserPromptSubmit nudge ("CRITICAL FIRST ACTION … call mem_context"), which contradicts its role and costs tokens.
  > - The Claude plugin's SubagentStop hook posts subagent output to `/observations/passive`, so writers that run as subagents (no Orca) can feed passive captures too.
  > - The Engram Codex plugin ships its own hooks as well.
  >
  > The Claude hook scripts have no opt-out environment variable (they read only ENGRAM_PORT/ENGRAM_URL and a Windows flag).
  >
  > Expected: worker sessions (Orca workers on any runtime, and subagent writers) neither register Engram sessions, capture prompts or passive observations, nor receive Engram context; the coordinator keeps its Engram use unchanged. odd-flow must keep working without Engram, without Orca and without the Orca plugin.

Disabling a plugin removes its hooks and MCP server. `--bare`, `--safe-mode`, `disableAllHooks` also drop odd-flow's hooks.
