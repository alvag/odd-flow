- S8 (design A from L2, approved with S9): token contract.
  - State dir: `$ODD_FLOW_STATE_DIR` when set and non-empty, else `~/.odd-flow` (home of the running user). Records live in `<state>/worker-tokens/` (directory mode 0700, created on demand).
  - Token: 32 lowercase hexadecimal characters from a cryptographic random source (16 bytes). Record file name: lowercase hex SHA-256 of the token's ASCII text. Record content: JSON `{"role": "<role>", "issuedAt": <milliseconds since epoch>}`, file mode 0600, created exclusively.
  - Marker line: `odd-flow-worker: <role> <token>`, role lowercase, appended by the ODD Flow Orca plugin as `"\n\nodd-flow-worker: <role> <token>\n"` to an orchestration dispatch that has a `# Role: <role>` line (existing role-line rule). The plugin writes the record before returning the rewritten prompt; if writing fails, it passes the prompt unchanged (no marker). It passes unchanged when the last non-empty line already is a tokened marker. A bare trailing `odd-flow-worker: <role>` no longer makes the plugin skip. `onError` stays `"pass"`. The plugin removes records older than the lifetime when it issues a new one.
  - `scripts/prompt-submit.py` (Claude Code, Codex, Antigravity), first prompt only, same last-line selection as today (pasted_content closing-tag skip): the marker marks a worker only when the line fully matches `odd-flow-worker: <role> <token>` (role case-insensitive with ASCII folding, token exactly 32 lowercase hex), the record exists, is a regular file, holds the same role, and `issuedAt` is no more than 15 minutes old and no more than 60 seconds in the future; the hook then consumes it, and only a successful `os.unlink` by this hook makes it valid. Sequential reuse of a token fails; simultaneous submission of one token to several sessions is outside the threat model and not guaranteed to have one winner (L10). A bare marker, an unknown, reused, expired, malformed or wrong-role token never marks a worker by itself. Any error in this path means "not marked by the marker" and never blocks the prompt.
  - Unchanged: the Orca preamble prefixes and the `# Role:` first-line rule; native subagent exemptions; behavior without the plugin.
