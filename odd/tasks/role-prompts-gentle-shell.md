- S3 (assumption, same source): `verify` makes one isolated preparation attempt; on a deterministic error in a command it built itself (wrong flag, typo, path it chose) it makes exactly one corrected attempt and reports both. At a second failure or a missing prerequisite (tool, network, space, permission) it stops setup, reports one setup blocker and lists the unrun checks as unverified, never passed; zero probes run when setup failed. Setup failure is reported apart from code findings.
- S4 (assumption, same source): `verify` severity uses the realistic domain: a failure that appears only with inputs outside any realistic use (values past safe numeric range, pathological sizes) is an advisory unless the request names those inputs; any file, flag or value a user can feed through the program's own commands is realistic, hand-edited files included; a rule set for one entry path holds for every path that creates the same data; an unrequested change to the output, error text or exit code of a command that existed at the base is change-caused and a blocker. When a real case needs a tool, network, install or configuration the scratch copy lacks, the check is reported unverified with its exact command; a fixture is never substituted and called met.
- S5 (assumption, source `gentle-shell/assets/agents/review-{risk,readability,reliability,resilience}.md`, "Review rules"): `review` gives each lens a short concrete checklist of what to flag, plus at least one explicit "do not flag" counterexample per lens, kept stack-neutral (odd-flow runs on any project; no React- or framework-specific rules).
- S6 (assumption, source `gentle-shell/assets/agents/review-risk.md`, "Review ledger contract"): `review` accepts only proof from the pinned change: a changed hunk, a path the candidate created, a differential test (base vs candidate) or a before/after command. A finding whose proof rests only on unchanged code is `pre-existing` or `base-only`, never `introduced`. The JSON return schema and the `proof_refs` format (`path:line or command`) that `refute` and the parent consume stay unchanged.

When the missing input is a surface, it derives the exact repo-relative candidate paths with reasons. The return block keeps every existing field.
